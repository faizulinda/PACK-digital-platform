# DP.SC.054 — Автоэкспорт сна из Apple «Здоровье»

> **Статус реализации (22.07.2026):** дизайн и АрхГейт/IntegrationGate пройдены, реализация отложена — ни одно проверенное приложение-мост (Health Auto Export, Apple Shortcuts напрямую, Health.md, vitalina) не даёт ежедневное авто-расписание бесплатно. Возврат — при решении пилота о разовой покупке. Детали → WP-20.

## Обещание

Длительность сна, время подъёма и пульс покоя из приложения «Здоровье» на iPhone попадают в журнал сна (`DS-health`) сами, без ручного ввода — раз в день, к утреннему Day Open.

## Для кого

**Технарь.** Требует одноразовую ручную настройку приложения-моста на телефоне пользователем (вне зоны действия агента).

## Что пользователь получает

1. **Метрики без ручного ввода.** Длительность сна, подъём, пульс покоя — автоматически в отдельном файле-источнике (`sleep-auto-YYYY-MM.md`), не смешиваясь с ручным журналом Ф1.
2. **Fallback на ручной ввод.** Если конвейер молчит (не экспортировалось, парсер не нашёл файл) — ручной журнал (Ф1) продолжает работать как есть, Day Open не остаётся без данных.
3. **Показ в Day Open.** Якоря восстановления читают оба источника (авто + ручной), последний по времени побеждает при конфликте на одну дату.

## Что НЕ входит в обещание

- Не покрывает метрики питания/веса, тренировки, HRV-аналитику Welltory — только сон и подъём.
- Не гарантирует переживание смены формата экспорта Apple/Health Auto Export без вмешательства (Эволюционируемость ⚠️, риск принят пилотом 22.07.2026 — ArchGate).
- Не настраивает приложение на телефоне за пользователя — начальная настройка (установка, разрешения, расписание экспорта) выполняется пользователем вручную.

## Как работает

```
iOS «Команды» (Shortcuts), персональная автоматизация по времени суток
        ↓ (вероятно требует тап-подтверждение — Apple не даёт отключить
        ↓  «Спрашивать перед запуском» для автоматизаций с данными здоровья)
Команда читает Sleep Analysis + Resting Heart Rate за вчера из «Здоровье»
        ↓
Записывает файл (JSON/текст) → iCloud Drive (папка HealthExport)
        ↓
Парсер (launchd, раз в день утром) → извлекает сон/подъём/пульс покоя
        ↓
DS-health/current/sleep-auto-YYYY-MM.md (новый файл, не трогает ручной sleep-log-YYYY-MM.md)
        ↓
Day Open читает оба источника → якоря восстановления в утреннем dashboard
```

**Решение 22.07.2026:** выбран Apple Shortcuts вместо Health Auto Export (требовал подписки для экспорта — не подошло пилоту) и вместо Health.md/vitalina. Плюс: 100% бесплатно, встроено. Минус: вероятный ежедневный тап-подтверждение из-за privacy-ограничений Apple на автоматизации с Health-данными (см. Обучаемость ⚠️, ArchGate).

## Сценарии

**С1:** Ночью телефон сам выгрузил JSON в iCloud → утром launchd запустил парсер → к Day Open в журнале уже есть вчерашняя длительность сна, пилоту не пришлось вспоминать и вписывать вручную.

**С2:** Apple обновил формат экспорта, парсер не смог прочитать файл → лог фиксирует ошибку, ручной журнал (Ф1) остаётся источником на этот день — Day Open не падает и не показывает пустоту.

**С3:** Пилот на несколько дней уехал без телефона под рукой для настройки — конвейер просто не производит файлов, ручной ввод продолжает работать как единственный источник, деградация плавная.
