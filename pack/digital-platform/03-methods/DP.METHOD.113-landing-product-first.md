# DP.METHOD.113 — Лендинг ведёт работающим продуктом, а не описанием фич

## Описание

На лендинге инструмента или SaaS главный Hero-блок показывает результат работы продукта (расчёт, разбивку, сгенерированный объект) прямо в первом экране — вместо описания фич. Пользователь видит ценность до скролла. Подзаголовок формулируется от результата пользователя, а не от возможностей продукта. Feature-буллиты (если нужны) перемещаются ниже fold.

## IPO

**Input:** лендинг инструмента (трекер, генератор, анализатор, калькулятор) + описание ключевой операции продукта

**Process:**
1. Определить ключевую операцию, которую делает продукт (считает, генерирует, анализирует).
2. Встроить результат этой операции в Hero: демо-объект с реальным расчётом/разбивкой/выводом.
3. Написать подзаголовок от результата пользователя («лист считает за тебя»), не от фичи («автоматический расчёт AC»).
4. Feature-буллиты — ниже fold.

**Output:** Hero-блок с живым демо вместо описания

## Пример

RollKeep (D&D character tracker): Hero до рефактора — «Автоматический расчёт AC, HP, атак». После — демо-кубик с разбивкой атаки по компонентам (класс + способность + enhancement), три блока «откуда это число» по SRD-правилам. Подзаголовок: «Лист считает за тебя». Правила отрисовки — строго SRD-only (открытая лицензия).

## Тест применимости

«Могу ли я показать результат работы продукта одним экраном без объяснений?» Если да — метод применим. Если продукт нельзя продемонстрировать вне данных пользователя (например, CRM без клиентов) — потребуются скриншоты или видео вместо живого демо.

## Антипаттерн

Hero-блок с заголовком «Мощный инструмент для X» и 6 буллитами фич. Результат: пользователь читает описание, а не видит ценность; conversion rate ниже.

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Описание фич — проще реализовать | Живое демо — показывает ценность сразу | Живое демо требует sample-данных и поддержки |
| Feature list легко обновлять | Демо мотивирует больше слов | Демо устаревает при изменении UI |
