# DP.METHOD.111 — Составное состояние предела из существующих UI-элементов

## Описание

При проектировании экрана достижения лимита (max profit, max bet, rate limit, quota) не создавать новый макет. Вместо этого — составить нужное состояние из уже существующих UI-элементов: приглушить неактивный выбор, оставить доступным escape-action (Cash Out / Cancel), заменить подпись поля ввода на статус-строку. Дизайнеру передаётся только проверка цвета строки и поведения на граничных значениях (длинные суммы, overflow).

## IPO

**Input:** экран с активным вводом данных (ставки, количество, баланс) + условие предела (max profit reached, quota exceeded, лимит ставки)

**Process:**
1. Перечислить существующие элементы экрана.
2. Для каждого элемента решить: приглушить / оставить / скрыть.
3. Escape-action (Cash Out, Cancel, Close) — оставить активным.
4. Статусную строку (место подписи поля ввода или subtitle) — заменить на human-readable причину предела.
5. Передать дизайнеру только: цвет строки + поведение при длинных значениях.

**Output:** составное состояние предела без нового макета

## Пример

Original Games (EvenBet): экран достижения max profit собран из существующих элементов — выбор карты/ставки приглушён, Cash Out остаётся активным, строка `Max profit reached` заменяет подпись поля ставки. Макет не рисовался.

## Тест применимости

«Есть ли в UI-библиотеке элемент для каждого визуального изменения?» Если да — составной метод применим. Если нужен принципиально новый паттерн взаимодействия — требуется макет.

## Антипаттерн

Заказывать новый макет «состояния предела» у дизайнера, когда все необходимые визуальные сигналы уже есть в системе. Результат: задержка на дизайн, рассогласование с визуальным языком приложения.

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Макет — «правильный» путь через дизайн-систему | Составное состояние — быстро и согласованно | Соблазн «сделать красиво» откладывает готовность |
| Кастомный компонент выглядит точнее | Существующие элементы сохраняют visual language | Кастомный компонент требует отдельной поддержки |
