# DP.M.333 Consistency-тест: идемпотентное переприменение

## 1. Определение

Паттерн теста для data-driven UI: (1) создать объект из пресета, (2) повторно применить те же входные параметры, (3) утверждать, что состояние не изменилось. Находит скрытые побочные эффекты без ручного перебора.

## 2. Проблема

Data-driven UI с накопленным состоянием (формы, конфигураторы, character sheets) может иметь скрытые побочные эффекты: повторное применение тех же значений незаметно изменяет состояние (hardcoded fallback срабатывает дважды, поле инкрементируется, смежное поле перезаписывается). Стандартные тесты проверяют правильность значений, но не идемпотентность.

## 3. IPO-паттерн

| Элемент | Описание |
|---------|----------|
| Входы | Набор пресетов; каждый пресет = полный набор входных параметров объекта |
| Обработка | Создать объект из пресета → snapshot состояния → переприменить те же параметры → сравнить со snapshot |
| Выходы | Список нарушений идемпотентности (где state изменился после повтора) |

## 4. Шаги метода

1. Перечислить все пресеты (все классы × виды × уровни или репрезентативная матрица)
2. Для каждого пресета: создать объект → `snapshot_before` → переприменить параметры → `snapshot_after`
3. Assert: `snapshot_before == snapshot_after`
4. Запускать на CI при каждом изменении state-логики

## 5. Применимость

Любой data-driven UI с накопленным состоянием: формы, конфигураторы, character sheets, корзина, настройки. Метод не проверяет правильность значений — только идемпотентность операций.
