# DP.METHOD.109 — Актор-первый scope: инструмент вместо экрана, когда актор — агент

## Описание

Перед тем как проектировать UI-экран под шаг ввода данных, следует проверить, кто фактически выполняет этот шаг. Если актор — агент (а не сам пилот/пользователь), UI-экран остаётся без пользователя и становится избыточным. В таком случае фичу закрывает переиспользуемый инструмент с интерфейсом «агент → скрипт», а не in-app экран загрузки.

## IPO

**Input:** описание шага фичи (что должен сделать пользователь), контекст того, кто реально выполняет этот шаг (пилот вручную / агент / внешняя система)

**Process:**
1. Определить фактического актора: кто именно выполняет этот шаг — пилот вручную, агент, скрипт, внешняя система?
2. Если актор — агент: UI-экран не нужен. Перейти к шагу 3.
3. Сформулировать интерфейс «агент → инструмент»: что агент передаёт (структурированный JSON, файл, параметры), что инструмент делает (сверяет дубли, dry-run по умолчанию, записывает только при явном флаге).
4. Закрыть требование скриптом с соответствующим интерфейсом.

**Output:** решение о форме реализации шага: UI-экран (актор — человек) или инструмент/скрипт (актор — агент)

## Пример

DS-budget F3 (загрузка банковской выписки) описывалась как экран in-app upload. По факту пилот пересылает выписки агенту как PDF/текст — агент структурирует данные в JSON, скрипт `import-transactions.mjs` принимает JSON, сверяет дубли по полной истории счёта и по умолчанию делает сухой прогон. Экран остался бы без пользователя. Фаза F3 закрыта без UI.

## Тест применимости

«Кто будет использовать этот экран в своей рабочей практике?» Если ответ — «агент, не сам пилот» → метод применим. Если экран используют оба — оценить частоту и выбрать основной сценарий.

## Антипаттерн

Проектировать UI для каждого шага ввода данных по умолчанию, не задав вопрос «кто фактически выполняет этот шаг». Результат: экран в приложении без реальных пользователей.

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Экран нагляден и привычен | Скрипт дешевле и подходит агенту | Экран кажется «настоящей» фичей, хотя пользоваться им некому |
| Сделать на будущее, вдруг пригодится человеку | Делать под фактического актора сейчас | Запас на будущее стоит разработки и поддержки без текущей пользы |

## Bias-Annotation

| Смещение | Направление искажения |
|----------|------------------------|
| Допущение «ввод делает человек» | По привычке шаг ввода данных приписывается человеку → экран проектируется по умолчанию, вопрос об акторе не задаётся |
