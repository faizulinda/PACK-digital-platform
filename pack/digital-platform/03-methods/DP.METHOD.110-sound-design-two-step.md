# DP.METHOD.110 — Двухшаговый процесс заказа звука для HTML5-продуктов

## Описание

Заказ кастомного звука для интерактивного продукта (HTML5-игра, мобильное приложение) делится на два последовательных артефакта: задача дизайна (саунд-дизайнер получает ТЗ со списком событий, сдаёт семплы с видео-превью, до двух итераций правок, финальный мастеринг) и задача подключения (разработчик интегрирует готовые ассеты). Разделение обязательно: разработчик не может начать без финальных файлов, дизайнер — без таблицы событий с неймингом.

## IPO

**Input:** описание интерактивного продукта; список игровых/UX-событий, требующих звука; работающая сборка для захвата видео-демонстрации события

**Process:**
1. Составить таблицу событий: имя звука (slug), фаза игры, комментарий (описание момента, характер звука).
2. Создать задачу дизайна для саунд-дизайнера: описание продукта + таблица событий + требования к сдаче (все семплы с неймингом из таблицы, видео-превью от команды, до двух итераций правок, финальный мастеринг).
3. Снять видео-демонстрацию каждого события тот, у кого есть работающая сборка.
4. После получения готовых семплов — создать задачу подключения для разработчика.

**Output:** два артефакта: (1) ТЗ с таблицей событий и видео-демонстрациями → передано саунд-дизайнеру; (2) финальные ассеты с неймингом → переданы разработчику как задача подключения

## Пример

EvenBet HTML5-игры: Blackjack, Baccarat, Holdem Guessem — каждый продукт закрыт двумя задачами (дизайн + подключение). Задача POKER-404083 оформлена аналогично для следующего продукта.

## Тест применимости

«Нужен ли кастомный звук, а не стандартная библиотека?» Да → метод применим. Если достаточно стандартной библиотеки — двухшаговый процесс избыточен.

## Антипаттерн

Создать одну задачу «добавить звуки», назначить разработчику. Результат: разработчик заблокирован отсутствием файлов или использует временные ассеты, которые затем придётся заменять.

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Одна задача проще для отслеживания | Два разных артефакта у разных исполнителей | Одна задача скрывает последовательную зависимость «ассеты готовы → подключение» |
| Начать разработку раньше | Начать только при готовых ассетах | Интеграция на временных звуках требует переделки |
