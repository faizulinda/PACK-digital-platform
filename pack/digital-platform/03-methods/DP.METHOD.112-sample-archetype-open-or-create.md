# DP.METHOD.112 — Open-or-Create для sample-контента

## Описание

Для demo/sample объектов приложения вводится поле-маркер архетипа (`sampleArchetypeId`). При повторном открытии «образца» приложение ищет существующую копию (облако → локальное хранилище) и открывает её, а не создаёт дубликат. Параллельно отправляется событие в аналитику с семантикой «открытие демо», позволяя строить воронку первичных и повторных взаимодействий с sample-контентом.

## IPO

**Input:** пользователь открывает sample/demo объект (кнопка «Try sample hero», «Open demo», «Use template»)

**Process:**
1. Проверить облачное хранилище на наличие объекта с `sampleArchetypeId = <id>`.
2. Если найден — открыть; отправить `sample_{entity}_open` в аналитику.
3. Если не найден — создать новый с маркером `sampleArchetypeId`; отправить то же событие.

**Output:** открытый sample-объект без дублирования; аналитика различает первичное создание и повторные открытия

## Пример

RollKeep: кнопка «Try a sample hero» вызывает `openOrCreateSampleHero(archetypeId)`. При повторном нажатии открывает уже созданный лист персонажа, а не создаёт второй. PostHog получает `sample_hero_open` — можно строить воронку «первый визит → создал демо-персонажа → повторил демо».

## Тест применимости

«Если пользователь нажмёт кнопку "попробовать" второй раз, ожидаем ли мы дубликат?» Если нет — метод применим.

## Антипаттерн

Создавать новый sample-объект при каждом нажатии без проверки существующих. Результат: в хранилище N копий одного образца; аналитика не различает «первый раз» и «повторный».

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Простое «создать» — меньше кода | Open-or-create — предсказуемо для пользователя | Первый вариант накапливает дубли |
| Создать каждый раз — проще тестировать | Маркер архетипа — явная идентичность | Маркер требует миграции при смене sample-контента |
