# DP.M.338 — Контроль доступа через группы атрибутов, а не поля

## Обещание

В backoffice с большим числом полей управление правами остаётся читаемым и не взрывается комбинаторно при росте количества ролей и полей.

## Описание

Логически связанные поля ресурса объединяются в именованные **группы атрибутов** по смыслу бизнес-процесса. Привилегия (просмотр / правка / добавление / удаление) назначается на группу целиком, не на каждое поле отдельно.

Пример:
- Группа «Лимиты ставок»: `min_bet`, `max_bet`, `max_win` → привилегии `limits.view`, `limits.edit`
- Группа «Параметры казино»: `house_edge`, `rtp`, `volatility` → привилегии `casino.view`, `casino.edit`

## Inputs

- Backoffice-ресурс с 10+ конфигурируемыми полями
- Несколько ролей администраторов с разными уровнями доступа

## Outputs

- Матрица прав: **роль × группа атрибутов** (вместо роль × поле)
- Семантические границы совпадают с бизнес-процессом и бизнес-ролями

## Алгоритм

1. Выделить логические группы полей по теме («кто отвечает за эти параметры?»).
2. Дать каждой группе имя, отражающее бизнес-процесс.
3. Назначить привилегии на группу, не на поле.
4. При добавлении нового поля — поместить в существующую группу или создать новую группу.

## Когда применять

- Ресурс имеет 10+ полей с разными бизнес-owner'ами
- Роли должны иметь разный доступ к разным аспектам ресурса

## Когда НЕ применять

- Ресурс имеет мало полей (≤5) — per-field права не создают проблемы
- Все роли имеют одинаковый доступ ко всем полям — группировка избыточна

## Ограничение

Если внутри одной группы нужны разные права на разные поля — группу нужно разбить на более мелкие.

## Forces

| Полюс | Полюс | Напряжение |
|-------|-------|------------|
| Точность (право на каждое поле) | Читаемость (право на группу) | Per-field даёт тонкую настройку, но матрица прав растёт как роли × поля |
| Стабильность групп | Появление новых полей | Новое поле приходится втискивать в группу или дробить группу |

## Bias-Annotation

| Смещение | Направление искажения |
|----------|------------------------|
| Группировка по технической структуре | Поля объединяются по таблице или экрану, где они лежат, а не по тому, кто за них отвечает → группы не совпадают с ролями и права снова приходится дробить |
