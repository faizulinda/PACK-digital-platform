# Sleep Export Parser — DP.ROLE.081

> # see DP.SC.054, DP.ROLE.081
>
> **Kind:** Transport/ETL Role — читает готовый файл, извлекает известные поля, пишет строго в свой файл. Без интерпретации, без записи поверх ручного журнала.
> **Owner Role:** пилот (IWE, локальный launchd на Mac).

## 1. Миссия

Быть мостом между экспортом Apple «Здоровье» (через Health Auto Export) и журналом сна DS-health — без участия пилота в рутинном переносе чисел.

**Граница:** не парсит произвольные метрики здоровья — только сон/подъём/пульс покоя (границы Ф4, DP.SC.054). Не пишет в ручной `sleep-log-YYYY-MM.md` — только в свой `sleep-auto-YYYY-MM.md`.

## 2. Обязанности

| Обязанность | Как выполняется |
|---|---|
| Найти свежий экспорт | Проверить путь iCloud-синхронизации на новый/изменённый JSON-файл |
| Извлечь метрики | Длительность сна, время подъёма, пульс покоя из JSON |
| Записать | Дописать строку в `DS-health/current/sleep-auto-YYYY-MM.md` |
| Не падать молча при сбое | Если файл не найден или схема не распознана — лог ошибки, выход без записи (ручной журнал остаётся источником) |

## 3. Входы / выходы

**Вход:** JSON-файл экспорта Health Auto Export (путь — из iCloud Drive).
**Выход:** строка в `sleep-auto-YYYY-MM.md` (дата, длительность сна, подъём, пульс покоя).

## 4. Ограничения

1. Идемпотентность: повторный запуск на тот же день не создаёт дубль строки.
2. Не интерпретирует данные — переносит числа как есть.
3. Не блокирует остальной Day Open при сбое (см. DP.SC.054 С2).

## 5. Связи с другими ролями

| Роль | Отношение |
|---|---|
| DP.ROLE.044 Notification Dispatcher | Не связаны — этот конвейер не шлёт уведомлений, только пишет в файл |
| Day Open (скилл) | Потребитель — читает `sleep-auto-*.md` при сборке утреннего dashboard |
