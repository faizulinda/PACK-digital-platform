# DP.FM.192 — Опциональный компонент не развёрнут — статус «серый», не «жёлтый»

## Описание

Dashboard с опциональными компонентами присваивает жёлтый статус («неизвестно» / `unknown`) когда скрипт не находит рабочий каталог или результаты компонента. Если компонент явно не инициализирован на данной установке, правильный статус — серый («не развёрнуто»), а не жёлтый («данных нет / сбой»).

## Симптом

Жёлтая строка в мониторинге появляется каждый день на установках, где компонент никогда не разворачивался. Пользователи привыкают к «перманентному жёлтому» и перестают обращать внимание на светофор. Реальный сбой тонет в шуме.

## Корень

Два состояния — «компонент не настроен» и «компонент настроен, данных нет» — сопоставляются одному значению `unknown`. Скрипт мониторинга не различает «отсутствие рабочего каталога» (компонент не установлен) и «рабочий каталог есть, но данных нет» (компонент не отработал или завис).

## Тест

«Есть ли в мониторинге явная метка `not-deployed` / серый статус, отличный от `unknown`?»
- Нет → все опциональные компоненты будут желтить дашборд на установках, где они не нужны.

## Правило

Для каждого опционального компонента dashboard должен различать три состояния:

| Состояние | Признак | Отображение |
|-----------|---------|-------------|
| Не заявлен | Нет конфигурационного маркера / рабочего каталога | Серый / пустой |
| Заявлен, данных нет | Каталог есть, результатов нет | Жёлтый |
| Работает | Результаты свежие | Зелёный / метрика |

Постоянный ложный жёлтый разрушает доверие к мониторингу.

## Пример

Компонент Scout не развёрнут на установке. Скрипт ищет каталог с результатами, не находит, подставляет `unknown` → светофор жёлтый каждый день. Исправление: проверить конфиг-маркер наличия Scout; если маркера нет — статус `not-deployed` (серый).
