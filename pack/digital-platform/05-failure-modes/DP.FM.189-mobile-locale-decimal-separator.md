# FM: iOS locale decimal separator — запятая вместо точки в числовых полях

## Паттерн ошибки

На iPhone с региональными настройками, где принята запятая как десятичный разделитель (Россия, Сербия, большинство стран Европы), цифровая клавиатура показывает запятую вместо точки. Любое числовое поле, валидирующее только точку (`/^\d+\.\d+$/`), отклоняет ввод — пользователь получает ошибку «Enter a valid bet amount» без объяснения причины.

## Почему это ошибка

iOS определяет десятичный разделитель на клавиатуре по **региональным настройкам устройства**, независимо от языка интерфейса приложения. Затронутые регионы охватывают большинство европейских пользователей. Ошибка silent: UI выглядит корректно, поле принимает ввод, но валидация молча отклоняет его без видимого сигнала о причине.

## Антипаттерн → Паттерн

| Антипаттерн | Паттерн |
|-------------|---------|
| Валидировать только точку: `/^\d+\.\d+$/` | Принимать и точку и запятую: `/^\d+[.,]\d+$/` |
| Отправлять ввод на бэкенд «как есть» | Нормализовать разделитель к точке перед отправкой: `value.replace(',', '.')` |
| Менять бэкенд под региональные форматы | Нормализация только на фронтенде — бэкенд не трогать |

## Тест обнаружения

1. Взять iPhone, сменить регион на «Россия» или любую европейскую страну.
2. Открыть любое числовое поле (ставка, множитель, Stop on Win, процент).
3. Ввести дробное число — клавиатура предложит запятую.
4. Отправить форму: если получаем ошибку валидации — уязвимость подтверждена.

## Затронутые поля

Все дробные поля: суммы ставок, множители, авто-кэшаут, Stop on Win, Stop on Loss, проценты комиссии.
