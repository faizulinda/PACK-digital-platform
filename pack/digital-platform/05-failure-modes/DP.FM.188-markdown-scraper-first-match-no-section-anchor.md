## [DP.FM.188] Markdown-скраппер якорится по форме колонок, а не по заголовку раздела

**Maturity:** seed

### Definition

Скрипт, инжектирующий строку в markdown-таблицу, ищет целевую таблицу по первому совпадению состава колонок (например, наличию колонки «РП»). Когда в документе появляется новая таблица со схожим набором колонок, скрипт выбирает первое совпадение вместо целевого раздела. Строка инжектируется в неправильную таблицу без явной ошибки.

### Category

**This failure mode is**: `method-failure`

### Observable Symptoms

- [ ] Новая запись появилась в таблице, отличной от ожидаемой.
- [ ] Поведение сломалось после добавления нового раздела с похожей структурой таблицы.
- [ ] В коде скрипта: поиск таблицы через `columns.includes('РП')` или аналогичный column-only match без проверки заголовка раздела.

### Root Causes

| Причина | Описание |
|---------|----------|
| Column-only anchoring | Скрипт проверяет только наличие нужных колонок, без проверки заголовка раздела. |
| Document growth | Документ изначально имел одну таблицу с данным набором колонок; со временем появились похожие. |
| Отсутствие regression-теста | Нет теста для документа с несколькими таблицами со схожим составом. |

### Consequences

- Данные попадают в неправильный раздел, искажая смысл обоих разделов.
- Ошибка проявляется только при изменении структуры документа, не при изменении скрипта.
- Требует ручного исправления уже опубликованных данных.

### Как избежать

1. Привязывать поиск таблицы к заголовку раздела (H2/H3) как anchor: сначала найти нужный заголовок, затем взять первую таблицу после него.
2. Проверять полный состав колонок (точное соответствие), а не только наличие ключевой.
3. Добавить regression-тест: документ с несколькими таблицами со схожим составом — инжекция должна попасть в правильную.
